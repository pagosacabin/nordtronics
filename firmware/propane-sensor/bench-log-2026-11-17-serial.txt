Both channels report every second; the 10 s INFO status line is the only view, because
ESPHome publishes raw sensor states at DEBUG. Values uncalibrated: MQ-6 ~1.47 V,
Figaro ~1.52 V, drifting down slowly as the heaters condition. Threshold here is 2.50 V
because the number entity restores its last value from NVS (see README); the yaml's
initial value is the brief's 1.0 V, which sits BELOW this rig's clean-air baseline and
therefore alarms on the first sample.

Probe-only build: identical alarm script, initial_value 2.0, plus two repeating interval
actions that set the threshold to 1.0 V every 25 s and 2.5 V every 60 s, so the trip and
the release both fire without an API client (the device has no network on the bench).

===== 4. Sensor-fault path (probe build pointing at 0x49, where nothing answers) =====

an unreadable channel fail SAFE instead of reading as clean air.
