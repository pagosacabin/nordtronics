### New Findings

**N1 (MEDIUM) — `README.md:84` documents `position` in the move request body, but `server.py` does not send it**
The API contract table in the README shows `{game_id, move, position, from_digest}` as the move request shape. The actual POST at `server.py:392–398` omits `position`. An operator writing their own backend from the README will expect and store a client-supplied position, re-opening finding #3 against any compliant-to-spec implementation. The spec and the code must agree.

**N2 (LOW) — `_get_api_base` fallback is called on every tool invocation; the warning fires repeatedly**
`server.py:63–76` calls `os.environ.get(...)` fresh each call and logs a `WARNING` on every invocation when the var is unset. Under normal MCP usage this spams stderr per tool call. A module-level cached call (or a `log.warning` call with `stacklevel` or a flag) would avoid the noise. Not a security issue, but an operational nuisance.

**N3 (NIT) — `local_api.py:216` default `store` argument hard-codes `/tmp/pc-games` in the function signature**
Finding #5 fixed the runtime `os.makedirs` permissions, but the `serve()` function's default parameter at line 216 still names `/tmp/pc-games`, meaning any caller who omits `store=` will use a world-visible-path name without necessarily knowing they need to pass a private path. The fix is cosmetic (remove the default or document it), but it slightly undermines the intent of finding #5's fix.
