1. do_OPTIONS 403: close_connection and drain
─────────────────────────────────────────────────────

server.py lines 406-410 (commit 125b3f0):

    if not origin_allowed(origin):
        self.close_connection = True
        self._send(403, {"error": "origin not allowed"}, origin)
        log("OPTIONS", self._path(), 403, "none", started)
        return

LOW-1 is PARTIALLY FIXED.

  • close_connection = True  ✓  — the critical half of the finding is
    resolved.  The server will not attempt to read a next request on
    this socket, so there is no pipelining / slot-accounting hazard.

  • drain=True               ✗  — the call passes only the positional
    arguments (status, payload, origin); the keyword argument drain
    defaults to False, so _drain() is not called.

Compare the 404 branch two lines above (line 403):

    self._send(404, {"error": "not found"}, origin, drain=True)

That branch does drain.  The 403 branch does not.  This is an
inconsistency.

Impact assessment: LOW (unchanged from the original finding, not
promoted to MEDIUM).

Rationale: an HTTP OPTIONS preflight carries no request body by spec
(Content-Length 0 or absent, no Transfer-Encoding).  With
close_connection=True the OS will RST the socket immediately after
the response is flushed; there is nothing to drain that could be
mis-parsed as a next request.  The omission is therefore cosmetically
inconsistent but not a correctness, security, or smuggling issue.

Recommendation: add drain=True to match the 404 branch and eliminate
the inconsistency:

    self._send(403, {"error": "origin not allowed"}, origin, drain=True)
